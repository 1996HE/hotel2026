# 要件確認・対応方針 — 白馬樹海 民宿管理システム

**作成日**: 2026-07-14  
**入力資料**: `民宿管理システム.xlsx`、現行ソースコード、README、DB マイグレーション、テスト結果

## 対応可否

**条件付き対応可能**

予約・客室・料金・清掃の主要業務は現行実装で動作し、2026-07-14 時点でフロントエンド品質チェックおよび JUnit 106 件が成功しています。一方、本番運用には、利用者認証、法定宿泊者名簿の不足項目、保存期間、監査ログ、AWS 上の可用性・監視を追加する必要があります。

## ご要件の理解

- 社内担当者が、予約、同行者、客室状態、清掃状態、期間別料金を一元管理する。
- 予約時に空室・清掃済み・定員・重複期間を確認し、宿泊日ごとの料金を確定する。
- 予約中、取消済み、チェックアウト済みを独立して一覧・ページングする。
- 宿泊終了日を迎えた予約を定期処理でチェックアウト済みに更新する。
- Spring Boot、React、MyBatis、PostgreSQL の現行資産を活用して本番運用へ移行する。

## 提案する進め方

1. **フェーズ0 — 法令・運用確定**: 宿泊者名簿項目、保存・削除方針、利用者ロール、AWS 接続方式を確定する。
2. **フェーズ1 — 業務・セキュリティ完成**: 認証・権限、法定項目、監査ログ、CSV 出力、既存画面のアクセシビリティを実装する。
3. **フェーズ2 — AWS 本番基盤**: ECS Fargate、RDS PostgreSQL、ALB、Secrets Manager、バックアップ、CI/CD を構築する。
4. **フェーズ3 — 非同期化・受入**: 自動チェックアウトを EventBridge/SQS ワーカーへ分離し、監視、E2E、負荷・障害試験を完了する。

## 確認させてください（不明点・前提条件）

- 本システムは旅館業法上の「宿泊者名簿」そのものとして利用しますか。それとも別の法定台帳がありますか。
- 宿泊者の住所、連絡先、外国人宿泊者の国籍・旅券番号・旅券写しを本システムで管理しますか。
- 予約管理、施設管理、運用管理の各担当者に、閲覧・更新・削除のどの権限を付与しますか。
- 社内 VPN、固定 IP、ID プロバイダーのどれで AWS 上の画面利用者を限定しますか。
- 取消済み・チェックアウト済み予約の「完全削除」は、法定保存・会計・監査要件と両立しますか。
- 目標 SLA、想定利用者数、客室数、予約件数、ピーク時間帯を確定できますか。

## リスク・注意点

- **高 — 法令項目不足**: 現行 DB に宿泊者住所がなく、外国人宿泊者向け項目もありません。法定台帳として使う場合は着手前に追加が必要です。
- **高 — 認証なし**: 現行アプリは業務 URL と API を `permitAll` としているため、ネットワーク境界だけでなく本人認証・権限管理を導入します。
- **高 — 物理削除**: 宿泊者名簿として保存すべき情報を削除できる現行機能は、保存期間と削除ルール確定まで本番で無効化します。
- **中 — 定期処理の多重実行**: アプリ内 Scheduler は ECS を複数タスクにすると重複実行するため、EventBridge/SQS に分離します。
- **中 — DB 実機検証**: 現行の高速 DB テストは H2 互換モードが中心です。PostgreSQL 18 / Flyway の CI 結合試験を追加します。
