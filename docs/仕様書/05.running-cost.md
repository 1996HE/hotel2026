# ランニングコスト試算書

**作成日**: 2026-07-14  
**通貨**: 日本円、税別  
**為替仮定**: 1 USD = 150円  
**対象構成**: 東京リージョン、社内向け小規模本番

## 1. 結論

初期のAWS利用料は **月額約1.5万円**、通常運用保守は **月額35万円**、障害対応の期待値は **月額14万円**、合計は **月額約50.5万円** と試算する。3年間TCOは開発費1,040万円を含め **約2,858万円** である。

価格は構成・為替・利用量・AWS料金改定で変わるため、契約前にAWS Pricing Calculatorで再計算する。以下は要件比較のための概算であり見積書ではない。

## 3. AWS月額

| サービス                 | 算定内容                                 |        月額概算 |
| ------------------------ | ---------------------------------------- | --------------: |
| ECS Fargate              | Web常時1task + 軽量Worker常時1task       |         3,600円 |
| RDS PostgreSQL           | 小規模Single-AZ、storage、backup超過少量 |         5,000円 |
| ALB / public IPv4        | ALB時間、低LCU、必要なIPv4               |         4,500円 |

| ECR                      | image 2GB以内                            |           100円 |
| Secrets Manager          | 2〜3 secrets、API少量                    |           150円 |
| SQS / EventBridge / SNS  | 毎時job、少量通知                        |           100円 |
| Route 53 / data transfer | private DNS、少量通信                    |           350円 |
| **合計**                 | 端数・為替変動を含む概算                 | **15,000円/月** |

NAT Gatewayを常設する場合はデータ処理費を除いても月額数千円規模が追加されるため、ECR/S3/CloudWatch/Secrets/SQSのVPC endpointと、要件に応じたegress方式を比較する。Multi-AZ RDS、Web常時2taskを選ぶ本番強化案は **月額3〜4万円程度** を目安とする。

## 5. 障害対応期待値

| 事象                               |  頻度仮定 | 1回工数 |   月平均工数 |

| 軽微（設定、再実行、利用問合せ）   |     月1回 |   0.5日 |        0.5日 |

## 7. SLA別シナリオ

| シナリオ | 構成差                                   |        AWS月額目安 | 適用                 |
| -------- | ---------------------------------------- | -----------------: | -------------------- |
| Pilot    | Web 1task、RDS Single-AZ、backup 7日     |            1.5万円 | 計画停止を許容       |
| Standard | Web 2task、RDS Multi-AZ、backup 14〜35日 |           3〜4万円 | 日常業務の停止を短縮 |
| Enhanced | Multi-AZ + DR snapshot、時間外当番       | 5万円以上 + 当番費 | 厳しいRTO/24h対応    |

可用性99.9%以上やRTO 1時間以内を求める場合、AWS費よりも時間外運用体制・復旧訓練の人件費が大きくなる。

## 8. コスト最適化

- 1〜2か月の実測後にFargate CPU/Memory、RDS class、log保持をrightsizingする。
- 安定後はCompute Savings Plans、RDS Reserved Instancesを比較する。
- CloudWatch LogsへPIIを出さず、30日後は必要な監査集約のみ低価格storageへ移す。
- NAT Gatewayを無条件で設置せず、VPC endpointと運用性を含めて比較する。
- 非本番は夜間停止し、環境別budget alarmを設定する。
