# 民宿管理システム 設計書案内

本フォルダの設計書は Excel に集約しています。

## 出力ファイル

- `民宿管理システム.xlsx`
- `民宿管理システム_フロントエンド設計書.xlsx`

## 含有内容

- 各シートの先頭に `作成日時` / `作成者` / `更新日時` / `更新者` / `備考` / `対象シート` を付与
- `docs/日本民宿予約管理システム_仕様書_ヘッダー追加.xlsx` の形式を参考に、表紙・変更履歴・概要・業務要件・機能一覧・コード行別処理仕様・画面一覧・DB設計・API一覧・非機能要件・テスト仕様・スケジュール・参考資料の13シート構成に整理
- Java コードの処理ロジック、DTO/API、DAO/Mapper、業務層 Service、Domain の責務は、機能一覧・コード行別処理仕様・DB設計・API一覧・参考資料の各シートへ分けて記載
- 2026-07-07 更新版では、`src/main/java/com/example/minshuku` 配下の Java 処理を Application / Config / Controller / Service / Mapper / Domain 単位に分解し、要件定義、基本仕様、業務規則、状態値、DTO、DB制約、SQL、テスト観点を詳細化
- 仕様書全体は、文書管理 → 概要 → 要件定義 → 基本設計 → 外部・データ設計 → 詳細設計 → 品質設計 → 管理情報の優先順で読めるように整理
- 詳細設計では、主要 Java 処理を実ファイル名・行番号・メソッド・コード行・処理内容の対応表として記載
- フロントエンド設計書も13シート形式で、React 画面、コンポーネント、API呼び出し、状態管理、CSS表示設計、コード行別処理仕様、単体テスト観点を記載
- テスト仕様は単体テストまでを対象とし、結合テスト仕様・総合テスト仕様は含めない
- テスト仕様シートには、テスト要望、テスト目標、前提条件、入力データ・操作、期待結果、判定基準、実施結果を記載
- 2026-07-08 更新版では、予約登録時のシステム日付基準判定、端末ローカル日時変更による過去日予約防止、`test_XX` 形式のテストケース番号、Javadoc 形式のテストケース注解、`System.out.print` によるテスト文字列結果を仕様へ追加
- 全 JUnit5 テストは `@LoggedTest` / `TestResultLogger` により、テスト開始、テスト内容、テストコード注解、テスト文字列結果、テストクラス文字列結果を Maven / VS Code コンソールへ出力
- 前端設計書にも、予約フォームの日付 `min` が `/api/reservations` の `today` を使用すること、テスト証跡を VS Code / Maven コンソールへ出力することを反映
- 2026-07-08 最新更新では、予約番号 `R000001` 形式、取消済み予約削除、削除済み客室の復元・完全削除、予約中客室の削除制限、チェックアウト済み予約だけの清掃更新制限を後端仕様へ反映
- 2026-07-08 追加更新では、チェックアウト済み予約削除、予約番号 `VARCHAR(16)` / `^R[0-9]{6,}$` 制約、予約サンプルデータ、削除済み予約・チェックアウト済み予約の API / テスト観点を後端仕様へ反映
- 前端設計書には、客室復元・完全削除ボタン、取消済み予約削除ボタン、チェックアウト済み予約削除ボタン、5件単位の一覧ページング、補完行による表高さ安定、刷新後 CSS レイアウトを反映

## 前提

- 対象システムは `http://localhost:8001/jukai-internal` 配下で動作する社内向け民宿管理画面です。
- 文書は現行の Spring Boot + React + MyBatis 実装を基準にしています。
- 画面、API、DB、テストは現行コードの仕様を優先しています。
