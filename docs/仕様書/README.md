## v1.11 の主な更新

- 管理者専用 `/calendar` に、客室を行・自然月の日付を列とする Tape Chart を追加
- 予約、確認待ち、滞在、退室済み、販売停止、メンテナンスを連続帯で表示
- 空期間の2点選択から、単一客室予約、販売停止、メンテナンスを登録
- `room_inventory_blocks` と追記型イベント履歴を追加し、全部・先頭・末尾・中間解除に対応
- 予約と在庫ブロックを `[開始日, 終了日)` で統一し、客室行ロック、排他制約、DBトリガーで相互競合を防止
- 公開多室申請の整単確認・拒否・取消と、客室単位の入住・退室を区別
- 退室後の清掃待ち、同日次客の清掃前入住拒否、客室単位の清掃完了を追加
- 表示中30秒更新、復帰時・操作直後更新、古い月要求の破棄を実装
- GitHubの成熟PMSは業務パターンだけを参考にし、コード・CSS・素材はコピーしない方針を明文化

## 客向けWebサイト v0.4 の主な内容

- 方案1「Alpine Pulse」を採用した、若く活発なスキーリゾート風の公開サイト
- `/stay` 以下にトップ、客室、料金、宿泊案内、周辺・交通、スキー場、予約リクエスト、予約照会、安全リンク取消の9画面
- 日本語、中国語、英語の切替とレスポンシブ表示
- 具体的な複数客室、客室ごとの人数・全宿泊者、日別料金明細を使う実予約申請
- 24時間の整单在庫保留、管理者の整单確認・理由付き拒否、期限切れ自動解放
- ハッシュ化した安全リンクによる入住72時間前までの取消
- 申請番号と申請時メールアドレスによる日中英の予約照会
- 照会結果の客室・日程・人数・料金・状態・拒否/取消理由表示
- 連続失敗5回後15分間の送信元制限と、予約の存在や不一致項目を漏らさない安全なエラー表示
- `pending` / `confirmed` のみを対象とした、理由入力・明示的再確認付きの72時間前までの整単取消
- `rejected` / `expired` / `cancelled` と取消期限超過後の読取専用表示
- SMTPとCloudflare Turnstileは環境変数で設定し、正式環境ではTurnstileを必須化
- 個人Gmailでのメール送信は一時保留し、公開配備時に共用送信アカウントへ切替予定。SMTP無効時も予約・照会・取消は継続
- 実住所、電話、メール、確定料金は「待設定」または「サンプル」と明示
- PC・スマートフォン、多言語、実予約、153件のJava・DBテスト、依存監査、視覚比較まで合格

## v1.10 の主な更新

- npm 間接依存の高危険度脆弱性を解消し、`npm run check` に `npm audit --audit-level=high` を追加
- チェックイン日とチェックアウト日から宿泊数を自動計算し、予約フォームと一覧へ読取専用表示
- `GET /api/reservations/available-rooms` を追加し、宿泊期間の重複、人数、定員、当日の空室・清掃状態で客室候補を絞り込み
- `CheckoutScheduler` の現行既定間隔を1分へ変更し、期限到来チェックアウトに加えて当日到着予約を `reserved` へ同期
- 同日後続予約がある退房では `reserved + needs_cleaning` を維持し、清掃完了後も `reserved` を上書きしない仕様へ修正

## シート構成

両ブックは、表紙、変更履歴、概要、業務要件、機能一覧、コード行別処理仕様、画面一覧、DB設計、API一覧、非機能要件、テスト仕様、スケジュール、参考資料に加え、後端は「運用・基盤仕様」、前端は「品質・配備仕様」を収録しています。

## 前提

- 対象 URL は `http://localhost:8000/jukai-internal` です。
- 現行の Spring Boot、React、MyBatis、PostgreSQL 実装を優先しています。
- 初回作成する単一ローカル管理者で認証し、管理画面・管理APIはセッション認証とCSRFで保護します。公開サイト/APIだけを明示的に匿名許可します。
- 現行 CI の DB 連携テストは H2 PostgreSQL compatibility mode です。PostgreSQL 実機と Flyway を使う専用テストは残課題として明記しています。
